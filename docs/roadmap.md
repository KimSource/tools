# 도구 추가 로드맵

아래는 도구와 탐색 기능의 구현 현황 및 후속 계획이며, 구현 순서는 정하지 않았습니다. 입력과 결과는 기존 도구와 동일하게 기기 안에서 처리하고 자동으로 영구 저장하지 않습니다.

## 도구 검색과 분류 후속 검토

- 태그를 직접 선택하는 필터 UI는 도구가 더 늘어났을 때 검토
- 새 도구를 추가할 때 Registry의 대표 카테고리·태그·한영 검색 키워드를 함께 정의

## Markdown Preview 후속 검토

- 외부 이미지 로드 시 사용자 선택과 개인정보 보호 방안
- 추가 코드 언어 지원
- 대용량 입력의 파싱·정제·렌더링 시간과 화면 반응을 측정하고, 필요하면 파싱·코드 강조의 Web Worker 이전 검토
  - DOM 정제와 렌더링은 메인 스레드에 남는 비용을 함께 확인
  - Worker 도입 시 오래된 결과 폐기와 lazy-load·오프라인 캐시를 검증

## Hash Generator 후속 검토

- 파일 해시: 입력 전체를 메모리에 올리는 API 특성을 고려해 파일 크기 제한과 대용량 처리 방식을 결정

## Time Zone Converter 후속 검토

- 브라우저별 Intl 시간대 데이터와 CLDR 식별자 차이 및 최신 데이터 갱신 검토
- 짧은 과거 오프셋 구간을 누락할 수 있는 연간 표본 조사의 정확도와 성능 개선 검토
- 모바일 및 다른 브라우저의 시간대 선택과 접근성 추가 검증

## QR Code 후속 검토

- HTTPS·카메라 권한 및 장치 선택·시작·종료 처리가 필요한 카메라 스캔
- Wi-Fi 연결 정보·연락처·이메일 생성을 위한 입력 양식

## Image Editor / Converter

크기 변경·압축·포맷 변환·자르기·회전·정보 확인을 하나의 이미지 편집·변환 도구로 제공합니다.

### 첫 단계 완료

- PNG·JPG·WebP 정지 이미지 한 장의 파일 선택·드래그 앤 드롭
- 파일명·실제 포맷·용량·방향이 반영된 가로×세로·가로세로 비율 표시
- 픽셀 또는 백분율 크기 변경, 비율 유지·확대 허용 선택
- PNG·JPG·WebP 변환, JPG·WebP 품질 조절 및 JPG 투명 영역 배경색 선택
- 명시적 결과 생성, 실제 결과 미리보기·원본 대비 바이트 용량·증감률·증가 안내와 다운로드
- 원본과 편집 설정을 현재 화면의 메모리에 유지하고 항상 원본에서 결과 생성; 원본으로 초기화
- 브라우저 출력 지원 검사 및 결과 MIME·시그니처 검증으로 잘못된 확장자 다운로드 방지
- 파일당 10 MiB, 총 1,600만 픽셀, 가로·세로 각각 최대 8,192px 제한; 출력에도 픽셀 제한 적용
- APNG·애니메이션 WebP를 파일 구조에서 감지해 거부하고 정지 이미지만 지원함을 안내
- 브라우저 표준 Canvas API와 순수 TypeScript 사용, 서버 전송·자동 영구 저장·신규 런타임 의존성 없음
- Registry lazy-load·한영 i18n·공통 파일 서비스 연계, 캐시 준비 후 오프라인 변환·다운로드

### 후속 단계

- 자르기: 자유 비율·원본 비율·1:1·4:3·16:9, 좌표·크기 숫자 입력
- 회전: 좌우 90도·180도
- 적용 순서: 방향 정규화 → 원본 좌표 기준 자르기 → 회전 → 크기 변경 → JPG 배경 합성 → 인코딩
- 애니메이션 보존과 편집·변환: 현재 첫 프레임 추출도 제공하지 않으며 별도 프레임 처리·메모리·출력 지원 검토 필요
- PNG 무손실 최적화: Canvas 재인코딩과 구분하여 필요성·의존성·번들 및 오프라인 캐시 영향 검토
- EXIF 상세 정보, 메타데이터 보존, 여러 파일 일괄 처리 검토
- 실제 모바일 기기 및 Safari·Firefox의 메모리·Canvas 한계·방향·색상·출력 품질 추가 검증
- 큰 이미지의 메인 스레드 처리 시간과 메모리를 측정하고 필요성이 확인되면 Web Worker, WASM, Offline Pack 순서로 검토

## 시간 관련 공통 구현 방침

- Date Calculator에서 도입한 Luxon을 시간대 변환기에도 사용한다. 임의 시간대의 날짜·시간 해석과 서머타임 처리를 담당한다.
- 다른 날짜·시간 도구는 실제 필요할 때 Luxon을 재사용한다. 계산 로직은 UI와 분리하고 도구 간 직접 import는 하지 않는다.
- Luxon은 필요한 도구 진입 시 lazy-load하고 Shell에서는 import하지 않음
- Luxon을 사용하는 도구를 추가할 때 초기 bundle·precache 변화와 오프라인 동작을 확인한다.
- Luxon도 브라우저의 `Intl` 시간대 정보를 사용하므로 별도의 최신 시간대 데이터베이스를 제공하는 것으로 간주하지 않음
- 연간 오프셋 목록은 별도 산출 로직이 필요하며, 1월·7월의 두 값만으로 확정하지 않음
- 검증에는 서머타임 시작·종료, 중복·누락 시각, 월말·윤년 및 연도에 따른 오프셋 목록을 포함
