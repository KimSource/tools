# 도구 추가 로드맵

아래는 아직 구현되지 않은 도구와 탐색 기능의 계획이며, 구현 순서는 정하지 않았습니다. 입력과 결과는 기존 도구와 동일하게 기기 안에서 처리하고 자동으로 영구 저장하지 않습니다.

## 도구 검색과 분류

- 도구 목록 상단에 검색창과 전체 / 텍스트·데이터 / 날짜·시간 / 이미지·디자인 카테고리 필터 제공
- 도구마다 대표 카테고리 하나와 기능을 나타내는 태그 여러 개 부여
- 검색은 도구 이름·설명·태그·한영 동의어를 대상으로 하며, 표시 언어에 관계없이 검색 가능
- 예: `이미지 압축`·`resize`로 이미지 도구 검색, `타임스탬프`·`timestamp`로 Timestamp 도구 검색
- 검색어와 선택한 카테고리를 함께 적용하고, 결과가 없을 때 안내와 조건 초기화 제공
- 태그는 우선 검색에 활용하고, 태그를 직접 선택하는 필터 UI는 도구가 더 늘어났을 때 후속 검토
- 카테고리·태그·검색 키워드는 Registry의 metadata로 정의하고 목록·검색·필터를 여기서 파생
- 카테고리·태그 ID는 `date-time`·`encoding`처럼 언어와 무관하게 유지하고 표시 이름은 타입이 지정된 ko/en 번역 키로 관리
- 검색은 도구의 UI·계산 모듈을 로드하지 않고 metadata만 사용하며, 오프라인에서도 동작

초기 카테고리 구성은 현재 도구와 추가 예정 도구를 함께 포함합니다.

- 텍스트·데이터 (`text-data`): JSON Formatter, Base64, Markdown Preview, URL Encoder / Decoder (구현됨), Hash Generator, Random String Generator
- 날짜·시간 (`date-time`): Unix Timestamp Converter (구현됨), Date Calculator, Time Zone Converter
- 이미지·디자인 (`image-design`): Color Converter, QR Code, Image Editor / Converter

태그 예시: Base64는 인코딩·디코딩·UTF-8, Hash Generator는 해시·SHA-256·체크섬, Image Editor / Converter는 크기 변경·압축·포맷 변환·자르기.

## Color Converter

- HEX ↔ RGB ↔ HSL 변환
- 컬러 피커와 색상 미리보기
- 형식별 색상 값 복사

## Markdown Preview

- Markdown 입력과 렌더링 결과를 나란히 표시
- 표와 코드 하이라이팅 지원
- Markdown 원문 파일 다운로드
- 원시 HTML 허용 범위와 렌더링 결과 정제 정책은 구현 시 결정
- 파서·하이라이터는 도구 진입 시 lazy-load하고 초기 bundle·precache 영향을 확인

## Hash Generator 후속 검토

- 파일 해시: 입력 전체를 메모리에 올리는 API 특성을 고려해 파일 크기 제한과 대용량 처리 방식을 결정

## Random String Generator

- 문자열 길이와 생성 개수 지정, 결과 복사
- 소문자 `a–z`·대문자 `A–Z`·숫자 `0–9`·특수문자를 각각 독립 체크박스로 선택
- 숫자만 선택하는 등 원하는 문자 종류의 조합 허용, 모두 해제하면 생성하지 않고 안내
- 특수문자 옵션에 실제 포함되는 문자 표시
- 혼동하기 쉬운 문자 제외 및 선택한 문자 종류를 각각 최소 1개 포함하는 옵션
- 브라우저의 암호학적 난수를 사용해 생성

## Date Calculator

- 하나의 도구 안에 날짜 차이 / 날짜 더하기·빼기 모드 제공
- 시각 없이 날짜만 다루며, 영업일·공휴일 계산은 범위에서 제외
- 날짜 차이: 시작일·종료일 사이의 총 일수와 주·나머지 일수 표시, 시작일 포함 여부 명시
- 날짜 더하기·빼기: 기준 날짜에 년·월·주·일 단위로 계산
- 월말·윤년 처리 규칙을 정하고 화면에 안내

## Time Zone Converter

- 기준 날짜·시간과 시간대를 입력하고 여러 대상 시간대로 변환, 날짜 변경 여부와 결과 복사 제공
- 기준·대상 시간대는 검색 가능한 드롭다운으로 선택
- 주 라벨은 현지화한 도시·국가명과 UTC 오프셋, 보조 라벨은 언어와 무관한 IANA 식별자 표시
- 오프셋이 여러 개인 지역은 입력한 날짜의 연도에 사용되는 값을 `/`로 구분해 표시하고 연도 기준임을 안내
  - 예: `뉴욕 · 미국 (UTC−05:00 / UTC−04:00)`, 보조 라벨 `America/New_York`
- 최종 결과에는 해당 시점의 실제 UTC 오프셋 하나를 표시
- 표시 언어와 관계없이 한글·영문 도시명·국가명, IANA 식별자, UTC 오프셋으로 검색
- 내 시간대·UTC를 상단에 제공하고, 나머지는 표시 언어의 도시 이름순으로 정렬
- 서머타임 전환으로 존재하지 않는 입력 시각은 안내 후 수정 요청, 중복되는 입력 시각은 가능한 오프셋을 보여주고 선택
- Unix Timestamp Converter는 UTC·로컬 표시를 담당하고, 여러 지역 시간 비교는 이 도구에서 제공

## QR Code

- 하나의 도구 안에 생성 / 읽기 모드 제공, 서버 전송이나 API 키 없이 기기 안에서 처리
- 생성: 텍스트·URL 입력, QR 미리보기, 크기 선택, PNG·SVG 다운로드
- 읽기: 이미지 파일 선택·드래그 앤 드롭, QR 내용 표시·복사
- 읽은 내용은 텍스트로 먼저 표시하고, URL은 사용자가 누르는 링크 열기 동작 제공
- 생성 라이브러리는 `qrcode`, 읽기 라이브러리는 `jsQR`을 후보로 검토
- `BarcodeDetector` 단독 사용은 브라우저 지원이 제한적이므로 디코딩 라이브러리 사용을 기본으로 검토
- 라이브러리는 도구 진입 시 lazy-load하고 도입 시 초기 bundle·precache 영향과 오프라인 동작 확인
- 후속 검토: HTTPS·카메라 권한 및 장치 선택·시작·종료 처리가 필요한 카메라 스캔
- 후속 검토: Wi-Fi 연결 정보·연락처·이메일 생성을 위한 입력 양식

## Image Editor / Converter

- 크기 변경·압축·포맷 변환·자르기·회전·정보 확인을 하나의 이미지 편집·변환 도구로 제공
- 첫 버전은 PNG·JPG·WebP 정지 이미지 한 장을 대상으로 하며, 파일 선택 후 편집부터 내보내기까지 이어서 진행
- 정보 영역: 파일명·포맷·용량·가로×세로·가로세로 비율 표시
- 크기 변경: 픽셀 또는 비율 입력, 가로세로 비율 유지, 확대 허용 여부 선택
- 자르기: 자유 비율·원본 비율·1:1·4:3·16:9, 좌표·크기 숫자 입력 제공
- 회전: 좌우 90도·180도
- 내보내기: PNG·JPG·WebP 선택, 결과 미리보기와 다운로드
- 압축: JPG·WebP 품질 조절, 실제 결과의 원본 대비 용량·감소율 표시, 원본보다 커지는 경우도 안내
- PNG 무손실 최적화는 기본 Canvas 품질 조절과 구분해 후속 검토
- JPG 출력 시 투명 영역을 채울 배경색 선택
- 브라우저의 출력 형식 지원을 확인하고, 요청과 다른 형식으로 생성된 결과를 요청한 형식으로 다운로드하지 않음
- 원본 이미지와 편집 설정을 유지하고 내보낼 때 최종 결과 생성, 원본으로 초기화 제공
- 기본 처리는 브라우저 표준 Canvas API를 우선 사용하며, 서버 전송 없이 공통 파일 서비스를 통해 파일 선택·다운로드 처리
- 큰 이미지의 메모리 사용을 고려해 입력 파일 크기·픽셀 수 제한과 오류 안내 기준을 구현 시 결정
- 애니메이션 이미지는 첫 버전에서 지원 대상이 아님을 안내하고, 애니메이션 보존과 편집·변환을 후속 지원 계획에 포함
- 후속 검토: EXIF 상세 정보, 여러 파일 일괄 처리

## 시간 관련 공통 구현 방침

- 시간대 변환기 구현 시 Luxon 도입: 임의 시간대의 날짜·시간 해석과 서머타임 처리를 단순화
- 다른 날짜·시간 도구도 실제 필요할 때 Luxon을 재사용하며, 계산 로직은 UI와 분리해 공유하고 도구 간 직접 import는 하지 않음
- Luxon은 필요한 도구 진입 시 lazy-load하고 Shell에서는 import하지 않음
- 도입 시 초기 bundle·precache 증가량과 오프라인 동작을 확인
- Luxon도 브라우저의 `Intl` 시간대 정보를 사용하므로 별도의 최신 시간대 데이터베이스를 제공하는 것으로 간주하지 않음
- 연간 오프셋 목록은 별도 산출 로직이 필요하며, 1월·7월의 두 값만으로 확정하지 않음
- 검증에는 서머타임 시작·종료, 중복·누락 시각, 월말·윤년 및 연도에 따른 오프셋 목록을 포함
