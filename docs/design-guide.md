# 디자인 가이드

## 방향과 적용 범위

Local Tools는 **넉넉하고 차분하지만, 입력과 결과는 빠르게 읽히는 도구 앱**을 지향한다. 회색 표면의 계층, 명확한 글자 위계, 여백, 주 행동의 강조를 디자인의 기본 원칙으로 삼는다. 색상은 프로젝트의 자체 팔레트로 관리한다.

현재 기준 구현은 [JSON Formatter](../src/tools/json-formatter/json-formatter.ts)다. [공유 스타일](../src/theme/tool-styles.ts)은 이 도구에만 적용되어 있다. 홈, 헤더, Base64에는 기존 스타일이 남아 있다. 새 도구 또는 기존 도구의 UI를 작업할 때 이 가이드를 참고하고, 적용 범위는 해당 작업에서 정한다. 문서가 있다는 이유로 다른 화면까지 일괄 변경하지 않는다.

실제 값은 공유 스타일을 기준으로 확인한다. 아래 수치는 현재 구현의 기준값이며, 동작과 가독성에 맞게 조정할 수 있다. 공통 기준을 바꾸면 코드와 문서를 함께 갱신한다.

## 시각 원칙

- 영역은 배경색과 간격으로 구분한다. 도구 바깥 패널은 유지할 수 있지만, 패널 안에 테두리와 그림자 카드를 반복하지 않는다.
- 그림자는 기본적으로 사용하지 않는다. 입력 영역은 옅은 회색 표면으로 구분한다.
- 제목과 핵심 결과를 강조한다. 설명과 보조 행동까지 모두 굵게 만들지 않는다.
- 파란색은 주요 행동에 집중한다. 상태와 설명은 필요 이상으로 강조하지 않는다.
- 입력 → 설정·실행 → 결과 → 결과 활용 순서가 자연스럽게 읽히도록 배치한다.
- 장식보다 작업 공간을 우선한다. 코드 입력과 결과에는 고정폭 글꼴을 사용한다.

## 색상

공유 스타일의 `--tool-*` 토큰을 사용한다. 도구마다 같은 역할의 색을 별도로 하드코딩하지 않는다.

| 토큰                | 역할                | 라이트    | 다크      |
| ------------------- | ------------------- | --------- | --------- |
| `--tool-surface`    | 도구 패널           | `#ffffff` | `#202226` |
| `--tool-field`      | 입력·보조 버튼 배경 | `#f3f4f6` | `#2b2e34` |
| `--tool-text`       | 본문·입력값         | `#20242b` | `#f2f4f6` |
| `--tool-muted`      | 설명·보조 행동      | `#626975` | `#aeb5bf` |
| `--tool-primary`    | 주 행동             | `#2563eb` | `#3978f6` |
| `--tool-focus`      | 키보드 포커스       | `#2563eb` | `#83afff` |
| `--tool-error-bg`   | 오류 배경           | `#fff0f0` | `#42272c` |
| `--tool-error-text` | 오류 텍스트         | `#b42332` | `#ffb4bd` |

토큰은 `light-dark()`로 정의하며 [기존 테마 서비스](../src/theme/theme.ts)가 설정하는 `color-scheme`을 따른다. 도구에서 별도 테마 상태나 저장 키를 만들지 않는다. Web Awesome의 브랜드·폼·포커스 토큰은 공유 스타일에서 연결한다. 렌더링된 버튼 색상은 컴포넌트의 상태 스타일에 따라 달라질 수 있다.

## 글자, 간격, 형태

| 요소           | 현재 기준                                              |
| -------------- | ------------------------------------------------------ |
| UI 글꼴        | 시스템 sans-serif; 외부 폰트 추가 없음                 |
| 도구 제목      | `clamp(1.75rem, 4vw, 2rem)`, 줄 높이 1.3, 자간 -0.03em |
| 설명           | 보조색, 줄 높이 1.6, 아래 간격 32px                    |
| 입력 라벨      | 굵기 600, 입력창과 간격 12px                           |
| 버튼           | 1rem, 굵기 600, 최소 높이 48px, 좌우 여백 20px         |
| 코드 입력      | 데스크톱 14px / 모바일 16px, 줄 높이 1.65              |
| 도구 패널      | 여백 32px, 반경 24px                                   |
| 입력창         | 최소 높이 220px, 여백 20px, 반경 16px                  |
| 버튼·오류 안내 | 반경 14px                                              |
| 작업 버튼 그룹 | 항목 간격 12px, 위 간격 20px, 다음 영역과 간격 36px    |

현재 모바일 분기는 600px 이하다. 패널은 여백 24px 16px·반경 20px, 입력창은 여백 16px을 사용한다. 이 수치는 모든 종류의 도구에 고정적으로 강제할 규격이 아니다. 결과가 숫자, 목록, 이미지인 도구에는 그 내용에 맞는 레이아웃을 사용한다.

## 컴포넌트와 상태

### 버튼

- 주 행동: `wa-button variant="brand"`. JSON Formatter에서는 정렬이 해당한다.
- 보조 행동: 기본 `wa-button`. 압축, 복사, 다운로드에 사용한다.
- 낮은 강조의 행동: `wa-button appearance="plain"`. 초기화 등에 사용한다.
- 결과가 없으면 결과 활용 버튼을 `disabled`로 둔다. CSS로만 비활성처럼 보이게 만들지 않는다.
- 모바일에서는 작업 그룹의 버튼을 셀 너비로 확장한다. 전역의 모든 버튼을 100% 너비로 만들지 않는다.
- 화면 하단 고정 버튼은 기본 패턴이 아니다. 필요할 때 가상 키보드, 스크롤, 결과 가림 여부를 확인하고 도입한다.

### 입력과 결과

입력창에는 연결된 `label`을 제공한다. Placeholder는 라벨을 대체하지 않는다. JSON Formatter는 네이티브 `textarea`를 사용하고, 결과에는 `readonly`를 지정한다. 같은 외형을 얻기 위해 Web Awesome 입력 컴포넌트로 교체할 필요는 없다.

테두리는 기본적으로 투명하게 두되 포커스는 2px outline과 3px offset으로 표시한다. 결과는 선택·복사할 수 있게 유지하고, 긴 내용 때문에 페이지 전체가 가로로 넘치지 않게 한다.

### 피드백

오류는 전용 배경·텍스트색과 구체적인 안내를 함께 제공하고 `role="alert"`로 알린다. 복사·다운로드 상태는 `role="status"`로 전달한다. 색만으로 상태를 구분하지 않는다. 새 문자열은 [ko/en i18n](../src/i18n/types.ts)의 타입이 지정된 key로 관리한다.

Hover, active, disabled, focus 상태는 Web Awesome 기본 동작을 존중한다. 상태를 덮어쓸 때는 라이트·다크에서 구별되는지 다시 확인한다. 새 모션을 추가한다면 작게 유지하고 `prefers-reduced-motion`을 고려한다.

## Lit에서 공유 스타일 사용하기

공유 스타일은 필요한 도구의 `static styles`에서 명시적으로 사용한다. Shell이나 전역 CSS에 import하지 않는다.

```ts
import { css, LitElement } from 'lit'
import { toolStyles } from '../../theme/tool-styles'

export class ExampleTool extends LitElement {
  static styles = [
    toolStyles,
    css`
      /* 이 도구에만 필요한 배치 */
      .controls {
        display: flex;
        flex-wrap: wrap;
        gap: 12px;
      }
    `,
  ]
}
```

공유 스타일은 `.tool`, `.description`, `.error`, `.result-actions span`과 `h1`, `label`, `textarea`, `wa-button`을 대상으로 한다. 사용하는 도구의 Shadow DOM 전체에 적용되므로 기존 마크업과 충돌을 확인한다. 공유 스타일을 가져온 것만으로 작업 그룹의 레이아웃까지 만들어지지는 않는다. `.controls`와 `.result-actions` 배치는 현재 JSON Formatter의 로컬 스타일에 있다.

CSS custom properties는 Shadow DOM 안으로 상속되지만, 전역 `wa-button::part(button)` 선택자가 다른 Lit 컴포넌트 내부의 버튼까지 관통하지는 않는다. 따라서 `::part()` 규칙은 공유 `CSSResult`로 각 도구에 포함한다. Web Awesome의 지원 part 이름은 설치된 버전에서 확인한다.

공통 색상·타이포그래피·입력·버튼 외형은 공유 스타일에, 도구별 배치·크기 예외는 도구 로컬 스타일에 둔다. 실제로 반복되는 패턴이 생겼을 때 공통화를 확장한다. 다른 도구를 직접 import하지 않고, Registry의 lazy loading 구조를 유지한다.

## 작업 시 확인할 사항

1. 먼저 공유 스타일과 기준 도구를 읽고 기존 패턴을 재사용한다.
2. 라이트·다크에서 본문, 보조 설명, 오류, 비활성 버튼과 포커스를 확인한다. 일반 텍스트 대비는 4.5:1을 목표로 확인하며, 현재 팔레트의 모든 컴포넌트·상태 조합이 검증되었다고 가정하지 않는다.
3. 320px 모바일 폭과 데스크톱에서 가로 넘침, 한·영 줄바꿈, 긴 입력·결과를 확인한다.
4. Tab 이동 순서와 포커스 표시, Enter/Space 버튼 실행, 라벨 연결을 확인한다. 강제 색상 모드에서 입력과 버튼 경계가 남아 있어야 한다.
5. 새 글꼴·아이콘·라이브러리는 필요성과 초기 bundle·precache 영향을 확인한다. 기본값은 브라우저 API와 기존 자산 재사용이다.
6. 코드·설정을 바꾸면 [README 검증 안내](../README.md#검증)에 따라 typecheck, lint, format check, unit test, build와 관련 E2E를 실행한다. PWA·업데이트 변경은 해당 추가 검증을 수행한다. 문서만 바꾸면 내용·링크를 확인한다.

디자인 변경 때문에 입력을 자동 저장하거나 서버로 전송하지 않는다. 파일·클립보드·저장소 작업은 기존 공통 서비스를 통한다.
